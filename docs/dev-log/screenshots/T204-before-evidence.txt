T-204 Advanced Layout Bug — BEFORE Evidence (Static Analysis)
=============================================================
Date: 2026-05-07
Method: Static CSS + HTML analysis (agent shell has no display per dev-log 035)

## Root Cause Identified

The `.schedule` grid section in preferences.css had three `:nth-child()` selectors
that assigned `grid-column: 1/2` (the left label column) to specific children:

  .schedule > :nth-child(1)  { grid-column: 1/2; grid-row: 1/6; ... }
  .schedule > :nth-child(9)  { grid-column: 1/2; grid-row: 8/12; ... }
  .schedule > :nth-child(17) { grid-column: 1/2; grid-row: 15/18; ... }

These selectors were designed for the pre-quota HTML structure where:
  - :nth-child(1) = miniBreaks section label
  - :nth-child(9) = longBreaks section label
  - :nth-child(17) = strictMode section label

## Observed bug (rendered path reasoning)

When quota mode is enabled and user clicks "Advanced" toggle:
  - .quota-advanced-content gets .hidden removed → becomes display:flex
  - BUT .schedule > :nth-child(9) rule fires:
      grid-column: 1/2  ← forces advanced content into LEFT label column (25% width)
      grid-row: 8/12    ← wrong row span
  - Result: the entire advanced content block is crammed into the narrow left
    column (25% width), causing severe layout overflow and text wrapping
  - The .quota-advanced-row items (label 180px min + range 200px) cannot fit
    in a 25%-wide column → visual chaos / overflow
