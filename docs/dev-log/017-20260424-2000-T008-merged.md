## 流程事件：Cross-task Lint 污染

**问题**：merger-T008 执行 merge 前最后一次 lint check 时，**lint 范围包含 T010 worktree 修改的文件**（共享 `app/` 目录）。

**时间线**：
1. T008 CR approved → merger-T008 准备 merge
2. Merger 执行 `npm run lint` → 失败，报错指向 T010 新增文件（app/commands.js 格式不符）
3. **T010 dev（dev-T010）** 无权 merge，但有权在自己 worktree 修复 lint
4. dev-T010 修复 lint（commit b84b7ab），同步推送 origin/feat/T010
5. Merger-T008 rebase 当前 HEAD → 获取 T010 lint fix → 重试 merge → 成功（12504bd）

**险境**：merger-T008 本应自主 lint 修复，但实际依赖 dev-T010 跨任务协作。如果 T010 lint 不及时修，T008 merge 会被永久阻塞。

## 缓解 + 教训

- **立刻缓解**：两个 worktree 都确认 lint 绿灯，允许 T008 merge 进行
- **根本原因**：eslint 配置 scope 过宽，include `app/**/*`，worktree 间无隔离
- **LESSONS.md 建议**（待 Checkpoint 评估）：
  ```
  eslint 范围包含共享目录时，pre-commit hook 应限制到当前 worktree changed files，
  或 per-task agent worktree 独立维护 .eslintignore，避免跨任务阻塞。
  ```
