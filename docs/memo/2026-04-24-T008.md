## 测试失败记录

### 失败 1：test mock 缺少 quotaManager + 接口不匹配

**现象**：`makeMockPlanner()` 不包含 `quotaManager` 字段；`makeQuotaManager()` 只实现 `getState()`，未实现 `getMiniQuota()/getLongQuota()/getTier()`。

**修复**：StatusMessages 改为通过 `qm.getState()` 读取 `{ miniQuota, longQuota, miniTier, longTier }`；`miniTier/longTier` 若 state 中存在直接用，否则 fallback 到 `qm.getTier()`（兼容真实 QuotaManager）。构造函数新增 `quotaManager` 直接参数（优先级高于 `breakPlanner.quotaManager`）。

### 失败 2：startBreak/startMicrobreak early-return 跳过 quota 块

**现象**：reference = `startMicrobreak` 时，quota 两行永远不追加——两个分支直接 `return message`。

**修复**：quota 模式下这两个分支不再 early-return，guard 改为 `if (schedulingMode !== 'quota') return message`，让执行流落到 quota 块。

## CR 修改记录

**CR 拒绝原因**：guard 条件 `!this.quotaManager` 语义不准确，依赖 null 值作为 classic 模式代理。

**修改内容**：两处改为 `this.settings.get('schedulingMode') !== 'quota'`，语义清晰且未来 classic 模式误传 quotaManager 时不会破坏行为。

## 接口决策记录

**决策**：StatusMessages 通过 `qm.getState()` 读 quota 值（miniQuota/longQuota），通过 `qm.getTier()` 读 tier。

**原因**：`getState()` 不含 tier 字段（test mock 的 miniTier/longTier 是 mock 扩展，非真实接口）。最终实现删除了 `state.miniTier` fallback 分支，直接调用 `qm.getTier()`——代码意图清晰，与真实 QuotaManager 接口对齐。这是第二次 CR AUTO-FIX 的内容。
