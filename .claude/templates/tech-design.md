### E2E 验证标注规则

涉及**外部 API、SDK、数据源集成**的任务，在上方任务分解表的 testing 列必须标注 `e2e`（而非 `atdd` 或 `post`）。

- **外部集成定义**：第三方 HTTP API、第三方 SDK、外部数据库、外部文件系统读写。内部模块调用不算
- **验证要求**：tech-QA 对标注 `e2e` 的任务，必须跑真实调用或使用真实数据 fixture 验证。纯 mock 测试不计入通过
- **PLANNING.md 标注**：架构师在任务分解时，识别涉及外部集成的任务并标注 `e2e`，确保 tech-QA 和 CR 能据此执行正确的验证策略

### 自动 Lint Hook（PostToolUse）

配置 PostToolUse Hook，在 Agent 每次编辑文件后自动运行 lint/format，避免格式问题进入 CR。

如果项目已有 lint 工具，直接使用；如果没有，按语言选择最通用的工具安装并配置：

| 语言/框架 | 推荐工具 | 命令 |
|---------|---------|------|
| TypeScript/JavaScript | Prettier + ESLint | `npx prettier --write $FILE && npx eslint --fix $FILE` |
| Python | Ruff | `ruff format $FILE && ruff check --fix $FILE` |
| Rust | rustfmt | `rustfmt $FILE` |
| Go | gofmt | `gofmt -w $FILE` |

Hook 配置写入 `.claude/settings.json`（项目级）：

```jsonc
// .claude/settings.json 中的 hooks 段
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "command": "[根据项目语言填写 lint 命令，$FILE 为被修改的文件路径]"
      }
    ]
  }
}
```
